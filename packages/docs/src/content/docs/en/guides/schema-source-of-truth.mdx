---
title: Schema Source Of Truth
description: Derive DTO types, runtime validation, OpenAPI, and RPC clients from one route schema object.
---

Croco route contracts should start from one schema object. The same object feeds request validation,
response contract metadata, contract graph snapshots, OpenAPI emission, and generated RPC client types.

## Decision

Use `defineRouteContract()` for REST controller routes that need one typed source of truth for method,
path, request schemas, and response schema:

- DTO types are inferred with `RouteParam`, `RouteBody`, `RouteQueryParam`, and `RouteMethodReturn`.
- REST decorators consume the same contract through `@Get(contract)`, `@Post(contract)`,
  `@Param(contract, "id")`, `@Query(contract, "name")`, and `@Body(contract)`.
- `buildContractGraph()` preserves those schema references in `inputSchemas` and `outputSchema`.
- `@croco/openapi-spec` and `@croco/rpc-codegen` derive artifacts from the contract graph instead of
  reading parallel DTO interfaces or hand-written OpenAPI metadata.

```typescript no-check
import {
  Body,
  Controller,
  defineRouteContract,
  HttpMethod,
  Post,
  type RouteBody,
  type RouteMethodReturn,
} from "@croco/protocols-rest";
import { z } from "zod";

const createUserInput = z.object({
  name: z.string().min(1),
  email: z.string().email(),
});
const userSchema = z.object({
  id: z.string().uuid(),
  name: z.string(),
  email: z.string().email(),
});

const createUserRoute = defineRouteContract({
  id: "users.create",
  method: HttpMethod.POST,
  path: "/users",
  body: createUserInput,
  response: userSchema,
});

@Controller("/users")
class UsersController {
  @Post(createUserRoute)
  createUser(
    @Body(createUserRoute) body: RouteBody<typeof createUserRoute>,
  ): RouteMethodReturn<typeof createUserRoute> {
    return { id: "4ea573de-cfb9-4696-bc48-216f19f44300", ...body };
  }
}
```

The controller has no separate `CreateUserDto` interface to keep synchronized. If the email schema
changes, the method parameter type, runtime validation, OpenAPI request body, and generated RPC request
type move together.

## Migration

Move existing loose decorators one route at a time. Replace the parallel path/param/body/response values
with a single route contract, then point the decorators at that contract:

```typescript no-check
const getUserRoute = defineRouteContract({
  id: "users.get",
  method: HttpMethod.GET,
  path: "/users/:id",
  params: z.object({ id: userIdSchema }),
  response: userSchema,
});

@Controller("/users")
class UsersController {
  @Get(getUserRoute)
  getUser(
    @Param(getUserRoute, "id") id: RouteParam<typeof getUserRoute, "id">,
  ): RouteMethodReturn<typeof getUserRoute> {
    return getUser(id);
  }
}
```

If the contract path declares `:id` but the params schema uses `userId`, `defineRouteContract()` fails
typecheck. If the controller binds `@Body(otherSchema)` or `@ResponseSchema(otherSchema)` against a
contract route, `buildContractGraph()` emits a contract diagnostic before OpenAPI or RPC generation.

## Considered Models

| Model                          | Strength                                                              | Tradeoff                                                                                                                 | Croco stance                                         |
| ------------------------------ | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| Route schema object            | One source feeds validation, graph snapshots, OpenAPI, and RPC types. | Controller decorators still attach the schema to route metadata.                                                         | Adopted now.                                         |
| TypeScript DTO interface first | Familiar for application authors.                                     | Runtime validation and OpenAPI need a second schema or codegen pass, creating drift risk.                                | Not sufficient alone.                                |
| OpenAPI first                  | Strong external contract artifact.                                    | Server runtime validation and TypeScript DTOs become generated consumers, which is heavy for local controller authoring. | Useful output, not the primary source.               |
| Library-neutral schema adapter | Keeps Croco independent of a schema library.                          | Needs a stable adapter contract before existing Zod users can migrate safely.                                            | Future extension point, not required for this slice. |

## Drift Gates

Generated contract artifacts must read the contract graph:

```typescript no-check
import { buildContractGraph } from "@croco/protocols-core";
import { emitOpenAPIFromContractGraph } from "@croco/openapi-spec";
import { generateClientFilesFromContractGraph } from "@croco/rpc-codegen";

const graph = buildContractGraph([UsersController]);

emitOpenAPIFromContractGraph(graph);
generateClientFilesFromContractGraph(graph, ".croco/client");
```

This keeps the drift boundary explicit. If route metadata contains unsupported shapes, missing path
parameters, multiple body schemas, or unsupported generated-client schema kinds, the graph/codegen path
fails before publishing artifacts.

## GraphQL SDL Contract Snapshots

GraphQL APIs use a different source of truth. The executable schema comes from code-first
`type-graphql` resolver metadata, so the review artifact is the compiled SDL plus Croco resolver
metadata rather than the REST Contract Graph.

Use `createGraphQLContractSnapshot()` after schema compilation:

```typescript no-check
import {
  createGraphQLContractSnapshot,
  diffGraphQLContractSnapshots,
  stringifyGraphQLContractSnapshot,
} from "@croco/protocols-graphql";

const schema = await createSchema();
const snapshot = createGraphQLContractSnapshot(schema, { resolvers: [HealthResolver] });
const diff = diffGraphQLContractSnapshots(baselineSnapshot, snapshot);
```

The snapshot version is `croco.graphql-contract.snapshot.v1`. It records:

- deterministic SDL for the compiled schema,
- root query, mutation, and subscription operations,
- resolver class names and Croco DI scope,
- method-level roles, guards, interceptors, and declared `GraphQLProblemResponse` mappings.

Generated GraphQL apps include `graphql-contract.snapshot.json`, `contract:snapshot`, and
`contract:check`. CI should run the check path before build/typecheck. Intentional GraphQL schema
changes update the snapshot with `contract:snapshot`; unintentional breaking SDL drift, resolver
removal, DI-scope changes, guard/interceptor/role changes, and Problem mapping changes fail the
contract check.

REST Contract Graph/OpenAPI/RPC and GraphQL SDL snapshots are sibling artifacts. Do not force GraphQL
through the REST Contract Graph; keep GraphQL review centered on SDL plus resolver metadata.

## Dependency Rationale

This model does not add a new external schema dependency. Croco already uses Zod for REST validation and
contract artifact generation. `defineRouteContract()` is a small contract helper over existing schema
objects, and its public type inference uses Zod's structural output type so package-local Zod instances do
not force a duplicate DTO interface.

If Croco later supports another schema library, it should be added behind the same route-schema contract
shape with explicit artifact tests for validation, OpenAPI, and RPC generation.
