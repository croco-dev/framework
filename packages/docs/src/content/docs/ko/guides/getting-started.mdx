## 1. 소개

Croco는 **SaaS 백엔드 툴킷**입니다 — auth, metering, billing, tenant 격리, REST 계약,
운영 진단을 프레임워크에 내장한 완전 타입 안전한 시스템입니다. `saas-api` goal은
지원되는 생성 스택을 선택하고 이를 `croco.app.json`에 기록합니다.

이 가이드는 하나의 실행 가능한 순환을 따릅니다: REST SaaS 워크스페이스를 생성하고,
설치하고, 자격 증명 없는 데모 스모크를 통과시키고, 라우트를 살펴본 뒤, 같은 생성
컨트롤러를 확장합니다.

<Aside type="tip" title="바로 동작하는 예제를 원한다면?">
  auth, metering, DI 배선을 갖춘 별도의 Lambda 레퍼런스는
  [`examples/quick-start-lambda`](https://github.com/croco-dev/framework/tree/trunk/examples/quick-start-lambda)로
  바로 이동하세요. 결제에 초점을 맞춘 레퍼런스는
  [`examples/saas-billing-golden-path`](https://github.com/croco-dev/framework/tree/trunk/examples/saas-billing-golden-path)를
  사용하세요.
</Aside>

## 개발 환경 지원

네이티브 Windows CLI/스캐폴드 개발 환경은 현재 Croco의 공식 지원 및 검증 범위
밖입니다. Windows 개발자는 WSL2 안의 Linux 툴체인을 사용할 수 있습니다.
[Microsoft의 WSL 개발 환경 가이드](https://learn.microsoft.com/ko-kr/windows/wsl/setup/environment)를
참고하세요. Croco는 WSL2 자체를 검증하지 않았습니다. Linux CI가 통과해도 WSL2를
인증하는 것은 아닙니다. 브라우저로 웹 애플리케이션에 접근하는 Windows 사용자에
대한 지원은 그대로 유지됩니다.

## 2. 빠른 시작

CLI로 표준 SaaS REST 워크스페이스를 생성합니다:

```bash
npx create-croco-app@latest my-saas-api --goal saas-api --scope @myorg --no-install --no-git
```

이 명령은 `saas-api` goal과 `@myorg` 패키지 스코프로 비대화형 실행됩니다.
`apps/api-server/src/controllers/SaasController.ts`,
`apps/api-server/src/controllers/OperationsController.ts`, provider와 tenant
매니페스트, `croco.app.json` goal 계약을 갖춘 REST SaaS 워크스페이스를 생성합니다.
`@myorg`는 자신의 패키지 스코프로 바꾸세요.

의존성을 설치하고 문서화된 성공 시나리오를 실행합니다:

```bash
cd my-saas-api && pnpm install && pnpm demo:smoke
```

성공이란 `demo:smoke`가 생성된 REST 계약 검사, 인메모리 SaaS 데모 플로우,
운영 스모크를 외부 자격 증명 없이 완료하는 것을 뜻합니다. 오래 실행되는 서버를
시작하지는 않습니다.

## 3. 생성된 REST API 살펴보기

생성된 Node REST 애플리케이션은
`apps/api-server/src/controllers/SaasController.ts`와
`apps/api-server/src/controllers/OperationsController.ts`를 등록합니다.
`SaasController`는 `/saas` 아래에 로컬 데모 라우트를, `OperationsController`는
`/ops` 아래에 헬스와 진단을 노출합니다.

데모 엔드포인트를 활성화한 상태로 생성된 애플리케이션을 시작합니다:

```bash
SAAS_DEMO_ENDPOINTS_ENABLED=true pnpm --filter @myorg/api-server dev
```

다른 터미널에서 인메모리 SaaS 런타임을 시드하고 결정적인 스모크 결과를 읽습니다:

```bash
curl -X POST http://localhost:3000/saas/demo/seed
curl http://localhost:3000/saas/demo/smoke
curl http://localhost:3000/ops/health
```

`/saas/demo/*` 라우트는 `SAAS_DEMO_ENDPOINTS_ENABLED=true`가 아니면 비활성화된 채로
유지되며 프로덕션에서도 비활성화됩니다. CLI `pnpm demo:smoke` 경로는 해당 HTTP
라우트를 열 필요가 없습니다.

## 4. 생성된 컨트롤러 확장하기

라우트 메타데이터와 Problem 응답이 이미 함께 보관된
`apps/api-server/src/controllers/SaasController.ts`에 REST 동작을 추가합니다:

```typescript no-check
import { Inject } from "@croco/framework-context";
import { SAAS_RUNTIME_STATE_TOKEN, runSaasDemoFlow, type SaasRuntimeState } from "../saasDemo";

@Controller("/saas")
export class SaasController {
  constructor(
    @Inject(SAAS_RUNTIME_STATE_TOKEN)
    private readonly runtimeState: SaasRuntimeState,
  ) {}

  @Post(seedSaasDemoRoute)
  @ProblemResponses(...routeProblemResponses(seedSaasDemoRoute))
  async seedDemo() {
    await assertDemoEndpointsEnabled();
    return runSaasDemoFlow(this.runtimeState.reset());
  }

  @Get(smokeSaasDemoRoute)
  @ProblemResponses(...routeProblemResponses(smokeSaasDemoRoute))
  async smokeDemo() {
    await assertDemoEndpointsEnabled();
    return runSaasDemoFlow(this.runtimeState.reset());
  }
}
```

라우트 메타데이터나 동작을 바꾼 뒤에는 생성된 계약 게이트와 성공 게이트를 다시
실행합니다:

```bash
pnpm contract:check
pnpm demo:smoke
```

`contract:check`는 유효하지 않은 REST 스키마나 Problem 계약에서 실패합니다.
`demo:smoke`는 같은 생성 워크스페이스가 프로필, 아키텍처, 런타임 정책, 계약,
SaaS 플로우, 운영, 잡 검사를 여전히 통과함을 증명합니다.

## 5. 별도로 체크인된 레퍼런스

스캐폴드 여정은 이 지점에서 끝납니다. 배포별 예제나 더 깊은 도메인 예제가
필요하면 생성 파일로 취급하지 말고 아래의 별도 체크인 레퍼런스를 사용하세요:

- [`examples/quick-start-lambda`](https://github.com/croco-dev/framework/tree/trunk/examples/quick-start-lambda)는
  Lambda export, auth, metering, DI 배선을 보여줍니다.
  `pnpm quick-start-lambda:smoke`로 검증하세요.
- [`examples/saas-billing-golden-path`](https://github.com/croco-dev/framework/tree/trunk/examples/saas-billing-golden-path)는
  checkout, retry, 트랜잭션 이벤트, 감사 프로젝션, 명시적 Problem 복구를
  보여줍니다. `pnpm saas-billing-golden-path:smoke`로 검증하세요.

저장소 수준의 `pnpm first-success:verify` 게이트는 공개 스캐폴드 명령과 이 생성
SaaS 라우트/런타임 둘러보기가 실제 CLI 계약과 일치하도록 유지합니다.

## 6. 다음 단계

동작하는 SaaS API를 만들었으니 Croco가 할 수 있는 일을 살펴보세요:

- **[아키텍처 가이드](/ko/guides/architecture/)** — Host, Transport, Build Target, 패키지 경계, 의존성 주입을 이해합니다.
- **[Schema Source Of Truth](/en/guides/schema-source-of-truth/)** — 하나의 라우트 스키마에서 DTO 타입, 검증, OpenAPI, RPC 클라이언트를 도출합니다.
- **[배포 레시피](/en/guides/deployment-recipes/)** — 명시적 텔레메트리와 실패 경계를 갖춘 Lambda, Cloudflare Workers, Node 서버 항목으로 배포합니다.
- **[Events Core](/en/guides/events-core/)** — 트랜잭션 일관성을 갖춘 이벤트 기반 워크플로우를 구축합니다.
- **[Retry Core](/en/guides/retry-core/)** — retry, backoff, circuit breaker로 복원력을 더합니다.
- **[CLI와 생성기](https://github.com/croco-dev/framework/tree/trunk/packages/create-croco-app)** — DDD API, 풀스택 등의 프리셋으로 새 프로젝트를 스캐폴드합니다.
- **[패키지 카탈로그](https://github.com/croco-dev/framework#readme)** — 도메인과 성숙도별로 정리된 135개 패키지를 둘러봅니다.
