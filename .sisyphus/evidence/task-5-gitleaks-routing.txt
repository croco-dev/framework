## 실행 단계 분석

### 라인 59: continue-on-error 조건
  continue-on-error: ${{ github.event_name == 'pull_request' }}

  - pull_request 이벤트: continue-on-error=true → 실패해도 CI 계속 진행 (warning-only)
  - push 이벤트 (trunk): continue-on-error=false → 실패 시 CI 중단 (blocking)

### 라인 73-80: 출력 메시지 분기
  if [ "$exit_code" -ne 0 ]; then
    if [ "${{ github.event_name }}" = "pull_request" ]; then
      echo "::warning::gitleaks detected potential secrets (warning-only for PR). Review the SARIF/text report."
    else
      echo "::error::gitleaks detected potential secrets on protected branch. Please review and resolve before merge."
    fi
  fi

  - PR: ::warning:: 어노테이션 (GitHub UI에 노란색 경고)
  - trunk push: ::error:: 어노테이션 (GitHub UI에 빨간색 오류)

### 라인 91: summary 문서화
  "- `gitleaks` secret scanning: blocking on trunk push, warning-only on PR"

  - 이미 PR vs trunk 차단 수준이 명확히 구분되어 문서화됨

## 결론

현재 설정이 올바르게 구분되어 있음:
  - PR 경로: warning-only (continue-on-error=true, ::warning:: 출력)
  - trunk push 경로: blocking (continue-on-error=false, ::error:: 출력)

"보안 전체가 warning-only"라는 오해 방지를 위해 summary 섹션(라인 91)에
이미 명확한 구분이 기재되어 있음. 추가 수정 불필요.
