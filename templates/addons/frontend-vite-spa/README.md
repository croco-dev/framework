# frontend-vite-spa

Vite 기반 React 단일 페이지 애플리케이션(SPA) 애드온.

## 개요

이 레시피는 **Vite + React SPA** 구성을 제공한다. 서버 사이드 렌더링(SSR) 없이 클라이언트에서 모든 렌더링을 처리하는 순수 SPA 방식이다.

> **Next.js를 사용하려면 이 레시피를 쓰지 않는다.** Next.js는 `opennext` 또는 `vercel` 옵션으로 별도 지원된다. Vite SPA와 Next.js는 같은 추상화를 공유하지 않으며, 서로 독립적인 레시피 경로다.

## 배포 방식

두 가지 배포 모드를 지원한다.

### 1. Node 단일 컨테이너

API 서버가 정적 파일을 함께 서빙하는 방식이다. 빌드된 SPA 파일을 Node.js 서버에서 직접 제공한다.

- 단일 컨테이너로 API와 프론트엔드를 함께 운영
- 인프라 구성이 단순하고 배포가 간단함
- 소규모 서비스나 초기 단계에 적합

### 2. SST Lambda + S3 분리

프론트엔드와 백엔드를 분리 배포하는 방식이다.

- S3에 정적 파일 업로드, CloudFront로 배포
- API는 Lambda로 별도 운영
- 트래픽이 많거나 CDN 캐싱이 필요한 경우에 적합

## 환경변수

| 변수           | 설명         | 기본값                              |
| -------------- | ------------ | ----------------------------------- |
| `VITE_API_URL` | API 서버 URL | 미설정 시 같은 origin의 `/api` 사용 |

`VITE_API_URL`을 설정하지 않으면 프론트엔드는 자신과 같은 origin의 `/api` 경로로 요청을 보낸다. 분리 배포 시에는 반드시 API URL을 명시해야 한다.

## 현재 지원 범위 (v1)

- SPA 전용. SSR은 v1에서 지원하지 않는다.
- SSR이 필요하다면 v2+ 로드맵을 참고하거나 Next.js 레시피를 사용한다.

## Next.js와의 차이

| 항목        | Vite SPA (이 레시피) | Next.js                  |
| ----------- | -------------------- | ------------------------ |
| 렌더링      | 클라이언트 전용      | SSR / SSG / ISR          |
| 배포 옵션   | Node 단일 / SST 분리 | opennext / vercel        |
| 추상화 공유 | 없음                 | 없음                     |
| 레시피 경로 | `frontend-vite-spa`  | `opennext` 또는 `vercel` |

두 레시피는 독립적이며 서로 전환하는 마이그레이션 도구를 제공하지 않는다.
